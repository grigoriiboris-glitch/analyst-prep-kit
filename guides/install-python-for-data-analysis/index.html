Как установить Python для анализа данных

К концу этой страницы у вас будет установлен Python, pandas, установленный в тот же Python, и двухстрочная проверка, подтверждающая и то, и другое. Вы также поймете неудачу, которая стоит новичкам больше часов, чем что-либо еще в этой теме: pip install pandas сообщает об успехе, а затем import pandas говорит, что такого нет. Это не сломанная установка. Это два Python, и на этой странице показано, как их увидеть.

Вот чем на самом деле заняться сегодня. Установите Python с сайта python.org, отметьте галочкой Добавьте python.exe в PATH на первом экране, затем установите пакеты с помощью python -m pip install pandas а не простой pip install pandas. Эти две детали предотвращают почти все проблемы, описанные ниже.

Краткая версия: один Python, пакеты, установленные через этот Python по имени, и виртуальная среда для каждого проекта, если у вас более одного проекта. Анаконда — это альтернатива, стоящая одного абзаца ниже, и прилагаемые к ней правила лицензирования имеют значение, если вы работаете где-либо с более чем 200 сотрудниками.

Причина pip может добиться успеха и import все еще может потерпеть неудачу - это одна из идей, поэтому она дает представление о картине.

1. Проверьте, что у вас уже есть

Перед пояснением: как вы думаете, сколько копий Python сейчас находится на вашем компьютере? Зафиксируйте число, а затем запустите проверку.

Python часто появляется без просьбы, в составе другого программного обеспечения. Установка еще одного поверх - это то, как люди в конечном итоге сталкиваются с проблемой в разделе 5. Так что сначала посмотрите. Откройте терминал, который в Окна означает «Командная строка» или PowerShell, а на Мак означает «Терминал», затем запустите:

python --version

В Окна есть вторая команда, которую стоит знать, и она более полезна, чем первая. py — это средство запуска Python, небольшая программа, которая поставляется с официальным установщиком Окна и знает обо всех Python на компьютере. Попросите его перечислить их:

py -0

Вот что это напечатало на моей машине рядом с версией python сообщает:

> python --version
Python 3.11.0

> py -0
 -V:3.14 *        Python 3.14 (64-bit)
 -V:3.12          Python 3.12 (64-bit)
 -V:3.11          Python 3.11 (64-bit)

Три Питона, и две команды расходятся во мнениях относительно того, кто из них главный. py по умолчанию — 3.14, отмечено звездочкой. Слово python достигает 3.11. Ни то, ни другое не является неправильным, и здесь ничего не сломано, но каждая инструкция пакета, которой вы будете следовать с этого момента, должна указывать, что она означает. Если вместо этого ваша машина сообщает «не распознана» или «команда не найдена», значит, у вас ее нет, что является самым простым случаем. Перейдите к следующему шагу.

2. Установите Python и один важный флажок

Перейти к python.org/downloads и возьмите ту версию, которую он вам предлагает. По состоянию на 8 августа 2026 года это Python 3.14.7. Любая версия 3.12 или новее подойдет для аналитической работы.

На самом первом экране установщика Окна внизу есть флажок с надписью Добавьте python.exe в PATH. Отметьте его, прежде чем нажать «Установить». PATH — это список папок, которые ваш терминал ищет при вводе команды, поэтому установка этого флажка делает слово python работать в терминале вообще. Оставьте этот флажок снятым, и каждая команда на этой странице вернет сообщение «не распознано», что читается как неудачная установка, а не таковой.

На Мак установщик не имеет такого флажка, потому что он устанавливает его за вас. Единственное, что нужно знать о macOS, это то, что python3 может уже существовать как часть системы, и вам следует оставить его в покое, а не заменять. Используйте тот, который вы установили.

Закройте терминал и откройте новый после установки. Терминал читает PATH при запуске и больше никогда не просматривает его, поэтому уже открытое окно не может видеть ваш новый Питон. На этот единственный факт приходится большая доля фраз «я установил, а оно все равно не работает».

3. Анаконда или python.org: все решает один вопрос

Перед объяснением: вы прочтете, что Анаконда предназначена «для науки о данных», а python.org — «простой Python». Что на самом деле изменится на вашей машине после выбора одного вместо другого?

Анаконда — это Python плюс несколько сотен уже установленных пакетов плюс собственный инструмент для установки дополнительных. Практическая разница заключается в том, что pandas, NumPy, matplotlib и Юпитер доступны в момент завершения, и вы полностью пропускаете следующий раздел. Стоимость составляет около 5 ГБ диска и вторую систему пакетов для изучения вместе с пип.

Вопрос, который решает это, не технический. Сколько человек работает в организации, в которой вы будете использовать это? Условия обслуживания Анаконда делают ее распространение бесплатным для частных лиц и организаций с численностью сотрудников или подрядчиков до 200 человек и требуют платной лицензии при количестве 200 и более человек. Этот порог учитывает государственные органы и некоммерческие организации, а не только компании. Использование в аккредитованных учебных заведениях для преподавания, обучения и исследований освобождается от подсчета.

Итак: обучение дома или в небольшой компании — любой выбор хорош, и Анаконда экономит вам время. Направляясь к крупному работодателю, установите его с python.org и используйте пункт, потому что это то, что вам будет разрешено там запускать, и стоит уже иметь привычки. Вот и все решение, и оно той же формы, что и в Какую базу данных SQL установить: выбирайте для ситуации, в которую вы попадаете, а не для списка функций.

Если вам нужно удобство Анаконда без размера, Миниконда — это тот же инструмент, в котором почти ничего не предустановлено. К нему применяются те же условия лицензии, поэтому это не меняет ответа на вопрос выше.

4. Установите pandas, чтобы она оказалась в нужном месте.

pandas — это библиотека, предоставляющая таблицы Питон. Без него в Python есть списки и словари, но нет понятия электронной таблицы с именованными столбцами. Установите его и три, которые всегда сопровождают его, вот так:

python -m pip install pandas numpy matplotlib openpyxl

Читайте команду слева направо, ведь форма – это весь урок. python это переводчик, к которому вы стремитесь. -m pip означает «запустить модуль пункт, принадлежащий этот устный переводчик". install и четыре имени — это фактический запрос. Написанный таким образом пакет может разместиться только в том Python, который вы назвали.

Четыре имени, кратко. pandas это таблицы. NumPy Это механизм быстрого набора чисел, на котором построен pandas, и он в любом случае устанавливается автоматически. matplotlib рисует графики. openpyxl это то, что позволяет pandas читать и писать .xlsx файлы, и это тот, о котором никто не упоминает до того дня read_excel завершается сбоем из-за ошибки отсутствия зависимости.

В Окна поменяйте местами python для py -3.14 если вы хотите уточнить, какой из них вы имеете в виду. py -3.14 -m pip install pandas является однозначным, и его явное указание требует шести символов.

5. Неисправность, показанная на реальной машине

Вот почему просто pip это рискованная привычка. На моей машине вопрос о трех разных способах жизни пипа дает два разных ответа и одну явную ошибку:

> pip -V
pip 26.1.2 from C:\Users\Mike\AppData\Roaming\Python\Python311\site-packages\pip (python 3.11)

> python -m pip -V
pip 26.1.2 from C:\Users\Mike\AppData\Roaming\Python\Python311\site-packages\pip (python 3.11)

> py -m pip -V
C:\Users\Mike\AppData\Local\Programs\Python\Python314\python.exe: No module named pip

Прежде чем читать дальше, скажите, что означает эта третья строка.

Голое слово pip это отдельная маленькая программа, расположенная в папке на PATH, и на этой машине она принадлежит Python 3.11. Так pip install pandas поместил бы pandas в 3.11. Но py, программа запуска, по умолчанию имеет версию 3.14. Все, с чем я бегаю py пошел бы искать в 3.14, ничего не нашел и сообщил бы ModuleNotFoundError: No module named 'pandas', через несколько минут после установки с надписью «Успешно установлено». Оба сообщения верны одновременно.

Теперь представьте себе свою собственную машину, с любыми py -0 перечислены. Если установить с одним словом, а запустить с другим, то на какой квадратик указывает каждая стрелка на картинке вверху? В этом вопросе весь провал, и python -m pip это ответ на этот вопрос, потому что обе стрелки указывают на одно и то же имя.

6. Виртуальная среда и почему она навсегда покончит с этим

A виртуальная среда — это папка, содержащая собственную копию Python и собственные пакеты, принадлежащие одному проекту. Работайте внутри него, и не останется никакой двусмысленности, потому что проекту доступен только один Питон.

Три команды. Сделать, переключиться на него, установить в него.

python -m venv .venv

# Windows
.venv\Scripts\activate

# Mac or Linux
source .venv/bin/activate

python -m pip install pandas matplotlib openpyxl

После активации приглашение вашего терминала получит (.venv) префикс, который является видимым признаком того, что вы находитесь внутри него. С тех пор, просто python и простой pip оба означают копии среды, и проблема двух Python не может возникнуть. Тип deactivate сделать шаг назад.

Делайте это для каждого проекта, а не один раз для всего. Вознаграждение наступит позже: проект, к которому вы вернетесь через шесть месяцев, все еще будет иметь те версии пакета, для которых он был написан, а не ту версию, к которой перешла ваша машина. Если проект находится в Git, добавьте строку чтения .venv/ к твоему .gitignore, поскольку папка большая, ее можно перестроить и она специфична для вашего компьютера. Git для аналитиков охватывает то, что еще принадлежит этому файлу.

7. Докажите, что все это работает

Установка не завершается, когда программа установки закрывается. Все закончится, когда выйдет стол. Запустите это в одной строке:

python -c "import pandas, sys; print(pandas.__version__); print(sys.version)"
3.0.2
3.11.0 (main, Oct 24 2022, 18:26:48) [MSC v.1933 64 bit (AMD64)]

Две строки, два факта. Первая — это версия pandas, которая доказывает, что пакет импортирован, а не просто загружен. Во втором указывается точный Python, который его нашел, и это часть, которую почти каждое руководство по установке упускает. Распечатайте оба, и вам никогда не придется угадывать, в каком ящике вы находитесь.

Затем создайте настоящую таблицу, потому что вы пришли именно за этим:

python -c "import pandas as pd; print(pd.DataFrame({'region':['East','West'],'sales':[790,560]}))"
  region  sales
0   East    790
1   West    560

Полное до и после

Оба раза цель одна: заставить pandas работать.

До

pip install pandas
python my_script.py

Это работает на машине с одним Python и не работает на машине с двумя. Ни в одной из команд нет названия версии, поэтому то, какой Python получит пакет и какой Python запустит сценарий, определяется PATH — параметром, который вы не выбирали и которого не видите. Когда он выходит из строя, появляется сообщение об отсутствии пакета, что указывает на необходимость переустановки пакета. Переустановка ставит его в то же неправильное место, быстрее.

после

python -m venv .venv
.venv\Scripts\activate
python -m pip install pandas matplotlib openpyxl
python -c "import pandas, sys; print(pandas.__version__); print(sys.version)"

Каждый шаг называет своего интерпретатора, а последняя строка выводит доказательство, а не предполагает его. Папка среды делает ответ на вопрос «какой Python» свойством проекта, а не истории вашего компьютера, поэтому одни и те же четыре строки ведут себя одинаково на вашем ноутбуке, на компьютере коллеги и при новой установке через год.

Что пошло не так и как это исправить

Шесть, на которые приходится почти все.

«Python не распознается как внутренняя или внешняя команда». Либо PATH не был отмечен во время установки, либо терминал уже был открыт во время установки. Сначала откройте новый терминал. Если это по-прежнему не удается, перезапустите установщик, выберите «Изменить» и отметьте параметр «ПУТЬ».

Модульнотфаундеррор сразу после успешной установки. Это раздел 5. Запуск python -m pip -V и python -c "import sys; print(sys.executable)" и сравните два пути. Если они не согласны, установите с помощью python -m pip и разногласия исчезли.

«среда с внешним управлением» на Мак или Линукс. Система защищает свой Python от ваших изменений, и это правильно. Не проталкивайте его мимо предложенного флага. Создайте виртуальную среду, как в разделе 6, и установите туда.

Разрешение отклонено или предложено использовать судо. Никогда не устанавливайте пакеты с sudo. Он записывается в системный Python, от которого зависит операционная система. Виртуальной среде вообще не нужны повышенные разрешения.

read_excel завершается с ошибкой из-за отсутствия дополнительной зависимости. pandas умеют читать .xlsx только через помощника. python -m pip install openpyxl и та же линия будет работать.

Терминал открывается там, где вы не ожидали. Новый терминал запускается в вашей домашней папке, а не рядом с вашим файлом. cd в папку, в которой находится ваш скрипт, перед его запуском, иначе ошибка будет связана с отсутствующим файлом, а не с отсутствующим пакетом.

Почему это работает

Этот механизм стоит понять один раз, потому что он делает каждую из этих ошибок читабельной, а не загадочной.

Когда вы вводите простую команду, ваша оболочка по порядку просматривает папки, перечисленные в PATH, и запускает первое найденное совпадение. Это все, что представляет собой PATH: порядок поиска. Так python и pip не являются названиями вещей, они являются победителями двух отдельных поисков, и ничто не гарантирует, что два победителя принадлежат друг другу. Добавление -m pip заменяет второй поиск поиском внутри первого победителя, поэтому двусмысленность исчезает. Виртуальная среда решает ту же проблему с другой стороны: при ее активации одна папка помещается в начале PATH, поэтому оба поиска по своей конструкции оказываются в одном и том же месте.

Это также объясняет решение, в которое никто не верит: открытие нового терминала. Процесс получает свою копию среды при запуске и сохраняет ее, поэтому терминал, открытый перед установкой, содержит PATH, существовавший до установки. Ничего не кэшируется и ничего не сломано; вы просто запрашиваете окно со старым списком.

Одно замечание по поводу написания этой страницы. Прежде чем дать ответ, он постоянно просил вас дать ответ, сколько у вас Python, что означает третья строка. Попытка дать ответ до того, как вы увидите правильный, достоверно повышает, насколько хорошо сохраняется правильный ответ, даже если попытка неверна (Бисра, Лю, Несбит, Салими и Винн, 2018, Обзор педагогической психологии, 30(3), 703–725). Угадать три и найти одно — вот что подтверждает факт.

Использование этого на вашей машине

Сделайте это по порядку один раз, и вы больше не будете бороться с установкой.

  1. Бегать py -0 перед установкой чего-либо, или which -a python3 на Маке. Знайте, что уже есть.
  2. Установите с python.org и отметьте PATH., если только вы не учитесь дома или в небольшой организации и не хотите иметь преимущество Анаконда.
  3. Тип python -m pip, никогда не голый pip. Сделайте это единственным способом написания, и привычка ничего не будет стоить.
  4. Одна виртуальная среда на проект, по имени .venv, созданный в тот же день, когда находится папка. Добавьте это в .gitignore немедленно.
  5. Завершите каждую настройку, распечатав доказательство.: версия пакета и sys.version вместе. Установка, которую вы еще не видели, импорт еще не является установкой.

Если у вас под рукой есть бумага, один дополнительный рисунок стоит пяти минут. Нарисуйте прямоугольник для каждого вашего Питон. py -0 в списке, затем нарисуйте стрелку, которую принимает команда установки, и стрелку, которую принимает команда запуска. Там, где приземлятся эти две стрелки, на вашем компьютере, находится ответ на каждое сообщение об ошибке в этом руководстве.
