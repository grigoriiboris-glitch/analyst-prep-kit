PostgreSQL: Практическое руководство по запросам
Полный редактированный конспект учебного модуля по системным функциям, приведению типов, работе с датами и операторам подзапросов в PostgreSQL.
Раздел 0. Старт и системный каталог
Урок 1. Проверка версии сервера через VERSION()
Цель урока: Получить точную информацию о запущенной версии и сборке базы данных PostgreSQL.
Техническое объяснение:
Встроенная функция VERSION() возвращает текстовую строку с подробными сведениями о сервере PostgreSQL. Эту функцию можно вызывать непосредственно в блоке SELECT без указания таблицы-источника (секции FROM).
Особенности терминологии:
Не следует путать стандарт языка SQL с конкретной СУБД. Функция VERSION() является проприетарной функцией PostgreSQL и отсутствует или отличается в других реляционных СУБД (например, в Oracle используется V$VERSION, в SQL Server — @@VERSION).
Пример запроса:SELECT VERSION() AS postgres\_version;
Разбор решения:
Функция вызывается без аргументов. Ключевое слово AS postgres\_version задает понятный псевдоним (алиас) для возвращаемого столбца.
Ожидаемый результат:
Строка со сведениями о версии базы данных во фрагменте postgres\_version.
postgres\_version
PostgreSQL 15.3 on x86\_64-pc-linux-gnu, compiled by gcc...

Урок 2. Анализ схемы через INFORMATION\_SCHEMA.TABLES
Цель урока: Изучить системный каталог метаданных и получить список доступных таблиц в пользовательской схеме public.
Техническое объяснение:
Представление INFORMATION\_SCHEMA.TABLES — это стандартный системный интерфейс (ANSI SQL), содержащий метаданные обо всех таблицах и представлениях текущей базы данных. Столбец table\_schema хранит имя схемы пространства имен, а table\_name — непосредственное имя объекта.
Особенности терминологии:
Поиски объекта базы данных только по имени недостаточно безопасны: таблицы с одинаковыми именами могут одновременно существовать в разных схемах (например, public.orders и staging.orders). Для извлечения пользовательских таблиц учебной среды применяется фильтрация WHERE table\_schema = 'public'.
Пример запроса:SELECT table\_schema,
table\_name
FROM information\_schema.tables
WHERE table\_schema = 'public'
ORDER BY table\_name;
Ожидаемый результат:
Список из 7 пользовательских таблиц учебной базы данных (customers, order\_items, orders, page\_events, payments, products, support\_tickets), отсортированный по алфавиту.

Раздел 1. Проекция и фильтрация данных
Урок 3. Назначение псевдонимов столбцов через AS
Цель урока: Переименовать выводимый столбец в итоговом наборе данных без изменения структуры исходной таблицы.
Техническое объяснение:
Оператор AS задает проекции новое имя (псевдоним) в контексте выполнения текущего запроса. Псевдонимы служат для повышения читаемости итоговых отчетов.
Важное предупреждение:
Не следует заключать имена псевдонимов в одинарные кавычки ('customer\_name'): в SQL одинарные кавычки обозначают строковый литерал, а не идентификатор столбца. Для стандартных псевдонимов кавычки не требуются.
Пример запроса:SELECT full\_name AS customer\_name,
city
FROM customers
ORDER BY id;

Урок 4. Фильтрация логических полей в секции WHERE
Цель урока: Отбрать строки по логическому условию типа BOOLEAN.
Техническое объяснение:
Секция WHERE выполняет построчную фильтрацию до этапа группировки или сортировки. В PostgreSQL логические значения обрабатываются с помощью конструкции IS TRUE / IS FALSE или прямого логического выражения.
Синтаксическая нюанс:
Не допускается запись вида active = 'true', так как значение в кавычках воспринимается как строка. Правильный синтаксис включает синтаксические конструкции active IS TRUE или просто WHERE active.
Пример запроса:SELECT id,
full\_name,
city
FROM customers
WHERE active IS TRUE
ORDER BY id;

Урок 5. Проверка неопределенных значений с помощью IS NULL
Цель урока: Найти записи с отсутствующими значениями в столбцах.
Техническое объяснение:
Маркер NULL указывает на отсутствие значения или его неизвестность. Согласно стандартам SQL, любое трехзначное логическое сравнение вида coupon = NULL даёт результат UNKNOWN (неизвестно), а не TRUE. Поэтому проверка на пропуск осуществляется исключительно с помощью специального оператора IS NULL (или IS NOT NULL для заполненных данных).
Пример запроса:SELECT id,
coupon
FROM orders
WHERE coupon IS NULL
ORDER BY id;

Урок 6. Регистронезависимый поиск по шаблону через ILIKE
Цель урока: Найти текстовые данные по шаблону без учета регистра букв.
Техническое объяснение:
Оператор ILIKE — специальное расширение PostgreSQL для регистронезависимого сопоставления текста с шаблоном (в отличие от стандартного LIKE, чувствительного к регистру).
\* Символ % заменяет любую последовательность символов произвольной длины (включая пустую).
\* Символ \_ заменяет ровно один символ.
Пример запроса:SELECT id,
full\_name,
email
FROM customers
WHERE email ILIKE '%@example.ru'
ORDER BY id;

Урок 7. Сортировка записей через ORDER BY
Цель урока: Упорядочить строки итогового набора данных по нескольким критериям.
Техническое объяснение:
Оператор ORDER BY задает детерминированный порядок строк. ASC обозначает сортировку по возрастанию (по умолчанию), а DESC — по убыванию. При совпадении значений первого столбца применяется второй критерий.
Пример запроса:SELECT id,
customer\_id,
order\_ts,
status
FROM orders
ORDER BY order\_ts DESC, id DESC;

Раздел 2. Типы данных, приведение типов и временные ряды
Урок 8. Явное приведение типов с помощью оператора ::
Цель урока: Выполнить явное преобразование текстовой строки в целочисленный тип INTEGER.
Техническое объяснение:
В PostgreSQL синтаксический оператор :: выполняет явное приведение типов (Type Casting). Выражение выражение::ТИП эквивалентно стандартной конструкции ANSI SQL CAST(выражение AS ТИП). Функция PG\_TYPEOF() позволяет проверить итоговый тип выражения.
Пример запроса:l
SELECT '42'::INTEGER AS parsed\_id,
PG\_TYPEOF('42'::INTEGER) AS result\_type;
| parsed\_id | result\_type |
| :--- | :--- |
| 42 | integer |

### Урок 9. Извлечение компонентов даты функцией `EXTRACT()`
\*\*Цель урока:\*\* Извлечь порядковый номер месяца из штампа времени `TIMESTAMPTZ`.
\*\*Техническое объяснение:\*\*
Функция `EXTRACT(part FROM timestamp)` извлекает определенные атрибуты даты или времени (например, `YEAR`, `MONTH`, `DAY`, `WEEK`, `DOW`). Столбец типа `TIMESTAMPTZ` (`timestamp with time zone`) содержит абсолютный момент времени с привязкой к часовому поясу.
\*\*Правило синтаксиса:\*\*
Наименование части даты (например, `MONTH`) указывается без кавычек, так как является ключевым словом языка.
\*\*Пример запроса:\*\*
```sql
SELECT id,
order\_ts,
EXTRACT(MONTH FROM order\_ts) AS order\_month
FROM orders
ORDER BY id;

Раздел 3. Агрегация и группировка
Урок 10. Подсчет строк с помощью COUNT(\*)
Цель урока: Вычислить общее количество строк в выборке.
Техническое объяснение:
\* COUNT(\*) подсчитывает абсолютно все строки, попавшие в результат фильтрации, независимо от наличия NULL в отдельных столбцах.
\* COUNT(column\_name) подсчитывает только те строки, где значение в указанном столбце не равно NULL.
Пример запроса:SELECT COUNT(\*) AS orders\_count
FROM orders;

Урок 11. Группировка данных через GROUP BY
Цель урока: Распределить записи по группам и рассчитать агрегированный показатель для каждой группы.
Техническое объяснение:
Оператор GROUP BY объединяет строки с одинаковыми значениями ключевых полей в отдельные группы.
Строгое правило PostgreSQL:
Все столбцы, указанные в блоке SELECT, обязательно должны быть либо оборованы в агрегатную функцию (COUNT, SUM, AVG, MIN, MAX), либо присутствовать в предложении GROUP BY.
Пример запроса:SELECT status,
COUNT(\*) AS orders\_count
FROM orders
GROUP BY status
ORDER BY status;

Раздел 4. Реляционные связи и подзапросы
Урок 12. Соединение таблиц через INNER JOIN
Цель урока: Объединить данные из двух связанных таблиц на основе совпадения внешнего ключа.
Техническое объяснение:
INNER JOIN сопоставляет строки из двух таблиц по условию, заданному в секции ON. В результат попадают только те пары строк, для которых условие связи возвращает TRUE. Если для строки из левой таблицы нет соответствия в правой, строка исключается из итогового набора.
Пример запроса:SELECT o.id AS order\_id,
c.full\_name,
o.status
FROM orders AS o
INNER JOIN customers AS c
ON c.id = o.customer\_id
ORDER BY o.id;

Урок 13. Проверка существования через оператор EXISTS
Цель урока: Отбрать только тех клиентов, для которых существует хотя бы один связанный заказ.
Техническое объяснение:
EXISTS — это предикат проверки существования строк, возвращаемых коррелированным подзапросом. В отличие от INNER JOIN, оператор EXISTS прерывает сканирование подзапроса сразу после нахождения первого совпадения и не приводит к дублированию строк родительской таблицы при наличии у клиента нескольких заказов.
Пример запроса:l
SELECT c.id,
c.full\_name
FROM customers AS c
WHERE EXISTS (
SELECT 1
FROM orders AS o
WHERE o.customer\_id = c.id
)
ORDER BY c.id;

### Урок 14. Отрицательная проверка существования через `NOT EXISTS`
\*\*Цель урока:\*\* Найти записи главной таблицы, у которых полностью отсутствуют связанные строки в подчиненной таблице.
\*\*Техническое объяснение:\*\*
Оператор `NOT EXISTS` возвращает `TRUE` для строки внешнего запроса только в том случае, если вложенный коррелированный подзапрос возвращает пустой набор данных. Это наиболее безопасный и оптимизируемый метод поиска изолированных записей (в отличие от `NOT IN`, который может дать некорректный результат при наличии `NULL` во вложенной выборке).
\*\*Пример запроса:\*\*
```sql
SELECT c.id,
c.full\_name
FROM customers AS c
WHERE NOT EXISTS (
SELECT 1
FROM orders AS o
WHERE o.customer\_id = c.id
)
ORDER BY c.id;
