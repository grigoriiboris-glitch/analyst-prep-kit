Урок 1. Выбор конкретных полей товара (SELECT)
\* Раздел: Блок 1 · Основы запроса
\* Тема: Оператор SELECT
\* Теория: Оператор SELECT определяет, какие именно столбцы необходимо включить в результирующий набор данных, а оператор FROM указывает таблицу-источник. Перечисляйте требуемые поля через запятую. Символ звёздочки (\*) выбирает абсолютно все столбцы таблицы, однако в профессиональной аналитике принято явно задавать только нужные поля для оптимизации нагрузки на СУБД.
Синтаксис:SELECT column\_a, column\_b
FROM table\_name;
\* Задание: Выведите из таблицы products только наименование товара (product\_name) и его цену (price).
\* Подсказка: Определите два атрибута, отвечающие за название и стоимость, и укажите таблицу-источник products.
\* Решение:
SELECT product\_name, price
FROM products;
\* Объяснение решения: В предложении SELECT явно указаны только столбцы product\_name и price, благодаря чему исключаются избыточные данные. Порядок строк не фиксирован, так как явная сортировка не применялась.
\* Ожидаемый результат: Таблица из 2 столбцов (product\_name, price) и 6 строк (по одной на каждый продукт, например: Laptop Pro — 120; Wireless Mouse — 25; Monitor 4K — 350).
\* Типичные ошибки: Использование SELECT \* вместо выбора конкретных полей или отсутствие запятой между наименованиями столбцов.
\* Самопроверка: Что произойдёт, если заменить перечисление полей на \*? Запрос вернёт все столбцы таблицы products, включая технические идентификаторы и категории.
Урок 2. Поиск трех самых дорогих товаров (ORDER BY, LIMIT)
\* Раздел: Блок 1 · Основы запроса
\* Тема: ORDER BY и LIMIT
\* Теория: Предложение ORDER BY управляет порядком сортировки записей: ASC — по возрастанию (применяется по умолчанию), DESC — по убыванию. Конструкция LIMIT N оставляет в итоговой выборке не более N первых строк и указывается после блока сортировки. Указание вторичного поля сортировки позволяет однозначно ранжировать строки при совпадении значений первого поля.
Синтаксис:SELECT product\_name, price
FROM products
ORDER BY price DESC
LIMIT 3;
\* Задание: Выведите наименование и цену трёх самых дорогих товаров. При совпадении стоимости отсортируйте позиции по названию в алфавитном порядке.
\* Подсказка: Упорядочьте цены по убыванию, задайте алфавитную сортировку наименований как второе условие и ограничьте вывод тремя записями.
\* Решение:
SELECT product\_name, price
FROM products
ORDER BY price DESC, product\_name ASC
LIMIT 3;
\* Объяснение решения: Сортировка price DESC выводит самые дорогие позиции первыми. Дополнительный параметр product\_name ASC гарантирует детерминированный порядок при равных ценах. Инструкция LIMIT 3 оставляет в результате только верхний тройку товаров.
\* Ожидаемый результат: Ровно 3 строки со столбцами product\_name и price: Monitor 4K — 350; Office Chair — 180; Laptop Pro — 120.
\* Типичные ошибки: Указание ASC вместо DESC (вывод самых дешёвых товаров) или пропуск предложения LIMIT.
\* Самопроверка: Что изменится в работе запроса, если убрать ключевое слово LIMIT 3? Запрос вернёт полный список товаров, отсортированный от наиболее дорогого к самому дешёвому.
Урок 3. Фильтрация клиентов по региону (WHERE)
\* Раздел: Блок 1 · Основы запроса
\* Тема: Фильтрация через WHERE
\* Теория: Конструкция WHERE отсекает строки, не соответствующие заданному логическому условию. В структуре SQL-запроса выражение WHERE располагается строго после FROM и перед ключевыми словами GROUP BY или ORDER BY. Текстовые литералы обязательно оборачиваются в одинарные кавычки.
Синтаксис:SELECT customer\_name, region
FROM customers
WHERE region = 'South';
\* Задание: Выведите имена и регионы только тех клиентов, которые относятся к региону 'South'.
\* Подсказка: Укажите фильтрацию по полю region с точным совпадением текстового значения.
\* Решение:
l
SELECT customer\_name, region
FROM customers
WHERE region = 'South';
\* \*\*Объяснение решения:\*\* Условие `WHERE region = 'South'` проверяет каждую запись и оставляет только клиентов из южного региона. Одинарные кавычки явно обозначают текстовый литерал.
\* \*\*Ожидаемый результат:\*\* 3 строки: Boris Petrov — South; Farid Ali — South; Irina Volkova — South.
\* \*\*Типичные ошибки:\*\* Написание строкового значения без кавычек или размещение `WHERE` до ключевого слова `FROM`.
\* \*\*Самопроверка:\*\* Какая ошибка возникнет, если написать `WHERE region = South` без кавычек? СУБД воспримет `South` как имя столбца и выдаст ошибку отсутствия атрибута.
### Урок 4. Поиск заказов без привязанного клиента (IS NULL)
\* \*\*Раздел:\*\* Блок 1 · Основы запроса
\* \*\*Тема:\*\* Проверка на неопределённое значение `IS NULL`
\* \*\*Теория:\*\* Маркер `NULL` указывает на отсутствие значения в ячейке. Для поиска таких записей используется специальный оператор `IS NULL` (а для поиска заполненных — `IS NOT NULL`). Обычное арифметическое сравнение `= NULL` не работает, так как `NULL` не равен ни одному значению, включая самого себя.
\*\*Синтаксис:\*\*
```sql
SELECT order\_id, total\_amount
FROM orders
WHERE customer\_id IS NULL;
\* Задание: Найдите заказы, у которых не заполнено поле customer\_id. Выведите номер заказа и его итоговую сумму.
\* Подсказка: Используйте специальное условие проверки на NULL для поля идентификатора клиента.
\* Решение:
SELECT order\_id, total\_amount
FROM orders
WHERE customer\_id IS NULL;
\* Объяснение решения: Конструкция customer\_id IS NULL отбирает только те транзакции, где клиент не был привязан к заказу.
\* Ожидаемый результат: Одна строка с показателями order\_id = 1016 и total\_amount = 60.
\* Типичные ошибки: Использование оператора сравнения customer\_id = NULL, который всегда возвращает ложь/неизвестность.
\* Самопроверка: Каким оператором отбрать все заказы, у которых клиент точно указан? Для этого применяется оператор customer\_id IS NOT NULL.
Урок 5. Вывод уникальных категорий (DISTINCT)
\* Раздел: Блок 1 · Основы запроса
\* Тема: Устранение дубликатов с помощью DISTINCT
\* Теория: Ключевое слово DISTINCT исключает повторяющиеся строки из результирующей выборки. Оно указывается непосредственно после SELECT. Если выбирается один столбец, каждое уникальное значение встретится в выводе ровно один раз. DISTINCT не выполняет автоматическую сортировку записей.
Синтаксис:SELECT DISTINCT category
FROM products;
\* Задание: Получите список всех категорий товаров без повторений.
\* Подсказка: Примените модификатор уникальности сразу после ключевого слова выборок.
\* Решение:
SELECT DISTINCT category
FROM products;
\* Объяснение решения: DISTINCT оставляет по одной строке для каждого уникального наименования категории из таблицы products.
\* Ожидаемый результат: Столбец category с тремя уникальными значениями: Electronics, Accessories, Home.
\* Типичные ошибки: Выполнение обычного SELECT category, при котором категории дублируются по количеству товаров в них.
\* Самопроверка: Удаляет ли оператор DISTINCT дублирующиеся строки из самой таблицы в базе данных? Нет, DISTINCT влияет только на отображение текущего результата запроса.
Блок 2. Расширенная фильтрация и условная логика
Урок 6. Поиск товаров по окончанию названия (LIKE)
\* Раздел: Блок 2 · Фильтрация и логика
\* Тема: Сопоставление с шаблоном LIKE
\* Теория: Оператор LIKE осуществляет фильтрацию текста по шаблону. Подстановочный символ % заменяет любую последовательность символов (включая нулевую длину), а символ \_ заменяет ровно один символ. Шаблон вида '%4K' находит строки, оканчивающиеся на символы 4K.
Синтаксис:SELECT product\_name
FROM products
WHERE product\_name LIKE '%4K';
\* Задание: Найдите все товары, название которых оканчивается на '4K'. Выведите только наименование.
\* Подсказка: Поместите знак процента перед искомой комбинацией символов.
\* Решение:
SELECT product\_name
FROM products
WHERE product\_name LIKE '%4K';
\* Объяснение решения: Знак % перед 4K разрешает любое количество вводных символов, требуя точного совпадения подстроки 4K в самом конце наименования.
\* Ожидаемый результат: Одна строка со значением Monitor 4K.
\* Типичные ошибки: Размещение символа % после 4K (поиск строк, начинающихся на 4K) или использование знака = вместо оператора LIKE.
\* Самопроверка: Какой шаблон требуется написать, чтобы найти товары, содержащие слово 'Pro' в любой части названия? Для этого используется шаблон LIKE '%Pro%'.
Урок 7. Отбор товаров в ценовом диапазоне (BETWEEN)
\* Раздел: Блок 2 · Фильтрация и логика
\* Тема: Фильтрация диапазонов BETWEEN
\* Теория: Оператор BETWEEN проверяет вхождение значения в заданный интервал. Обратите внимание: обе границы диапазона (AND) всегда включаются в выборку. Условие легко комбинируется с предложением сортировки ORDER BY.
Синтаксис:l
SELECT product\_name, price
FROM products
WHERE price BETWEEN 25 AND 120;
\* \*\*Задание:\*\* Выведите товары стоимостью от 25 до 120 включительно. Покажите название и цену, отсортировав результат по возрастанию цены.
\* \*\*Подсказка:\*\* Используйте `BETWEEN` для задания диапазона и добавьте явную сортировку `ASC`.
\* \*\*Решение:\*\*
```sql
SELECT product\_name, price
FROM products
WHERE price BETWEEN 25 AND 120
ORDER BY price ASC;
\* Объяснение решения: BETWEEN 25 AND 120 отбирает позиции с ценами от 25 до 120. Конструкция ORDER BY price ASC упорядочивает их от самых дешевых к более дорогим.
\* Ожидаемый результат: 4 строки: Wireless Mouse — 25; Desk Lamp — 38; USB-C Hub — 45; Laptop Pro — 120.
\* Типичные ошибки: Использование строгой фильтрации через > и <, исключающей граничные значения 25 и 120.
\* Самопроверка: Попадёт ли в результат позиция с ценой 25.00? Да, так как оператор BETWEEN включает обе границы интервала.
Урок 8. Сегментация товаров по ценовым категориям (CASE WHEN)
\* Раздел: Блок 2 · Фильтрация и логика
\* Тема: Условные выражения CASE WHEN
\* Теория: Конструкция CASE WHEN реализует логику ветвления непосредственно в запросе. Выражения проверяются последовательно сверху вниз. СУБД возвращает результат первого выполнившегося условия THEN и прекращает дальнейшие проверки. Блок ELSE задаёт значение по умолчанию, а ключевое слово END завершает выражение.
Синтаксис:SELECT product\_name,
CASE
WHEN price < 50 THEN 'Budget'
ELSE 'Standard'
END AS price\_band
FROM products;
\* Задание: Создайте вычисляемое поле price\_band: если цена меньше 50 — 'Budget', от 50 до 199.99 — 'Standard', от 200 и выше — 'Premium'. Выведите название, цену и ценовую категорию.
\* Подсказка: Начните проверку с наименьшего порога (< 50), затем укажите порог < 200, а для остальных значений примените ELSE.
\* Решение:
SELECT product\_name, price,
CASE
WHEN price < 50 THEN 'Budget'
WHEN price < 200 THEN 'Standard'
ELSE 'Premium'
END AS price\_band
FROM products
ORDER BY product\_name;
\* Объяснение решения: Если цена менее 50, присваивается 'Budget'. Для оставшихся товаров проверяется условие < 200 (получают маркер 'Standard'). Все товары от 200 и выше попадают в ветку ELSE ('Premium').
\* Ожидаемый результат: 6 строк со столбцами product\_name, price, price\_band. Примеры: Desk Lamp — 38 — Budget; Office Chair — 180 — Standard; Monitor 4K — 350 — Premium.
\* Типичные ошибки: Нарушение порядка условий (например, размещение проверки price < 200 первой приведет к тому, что товары дешёвой категории перекроются условием Standard).
\* Самопроверка: Какую категорию присвоит данный запрос товару с ценой ровно 50.00? Первое условие (< 50) вернёт ЛОЖЬ, поэтому товар перейдёт ко второму условию (< 200) и получит статус 'Standard'.
Урок 9. Замена пропущенных значений в контактах (COALESCE)
\* Раздел: Блок 2 · Фильтрация и логика
\* Тема: Функция COALESCE
\* Теория: Функция COALESCE принимает список аргументов и возвращает значение первого из них, не равного NULL. Она идеально подходит для подстановки значений по умолчанию в отчётах без изменения данных в исходных таблицах.
Синтаксис:SELECT COALESCE(email, 'email missing') AS email\_contact
FROM customers;
\* Задание: Выведите имя каждого клиента и поле email\_contact. Если адрес электронной почты отсутствует (NULL), выведите строку 'email missing'.
\* Подсказка: Передайте функции COALESCE первым аргументом столбец email, а вторым — запасную текстовую подпись.
\* Решение:
SELECT customer\_name,
COALESCE(email, 'email missing') AS email\_contact
FROM customers;
\* Объяснение решения: Для клиентов с заполненным e-mail функция возвращает их реальный адрес. Если в поле email находится NULL, возвращается второй параметр 'email missing'.
\* Ожидаемый результат: 12 строк с полями customer\_name и email\_contact. Примеры: Alice Morgan — alice@example.com; Denis Ivanov — email missing.
\* Типичные ошибки: Попытка обработки пустой строки '' вместо истинного NULL (напоминаем, что COALESCE реагирует исключительно на NULL).
\* Самопроверка: Что вернёт COALESCE(NULL, NULL, 'Default')? Функция пропустит первые два значения NULL и вернёт 'Default'.
Блок 3. Агрегатные функции и группировка
Урок 10. Расчёт показателей каталога (COUNT, SUM, AVG)
\* Раздел: Блок 3 · Агрегации
\* Тема: Агрегатные функции COUNT, SUM, AVG
\* Теория: Агрегатные функции сводят множество значений столбца к одному итоговому показателю. COUNT(\*) считает общее количество строк, SUM вычисляет сумму арифметических значений, а AVG определяет среднее арифметическое. Без предложения GROUP BY агрегатные функции рассчитываются по всей таблице единовременно.
Синтаксис:SELECT COUNT(\*) AS row\_count,
SUM(price) AS total\_price,
AVG(price) AS average\_price
FROM products;
\* Задание: Выведите одну строку с тремя расчетными полями: products\_count (количество товаров), catalog\_value (общая сумма цен) и average\_price (средняя цена товара).
\* Подсказка: Примените три соответствующие агрегатные функции к таблице products и задайте им понятные псевдонимы.
\* Решение:
SELECT COUNT(\*) AS products\_count,
SUM(price) AS catalog\_value,
AVG(price) AS average\_price
FROM products;
\* Объяснение решения: Функция COUNT(\*) подсчитывает общее число товаров, SUM(price) суммирует ценники, а AVG(price) делит общую сумму на количество заполненных цен.
\* Ожидаемый результат: Итоговая строка: products\_count = 6; catalog\_value = 758; average\_price = 126.33.
\* Типичные ошибки: Путаница с назначением функций, например использование COUNT(price) для расчета суммы или незаполнение псевдонимов столбцов.
\* Самопроверка: В чём разница между COUNT(\*) и COUNT(price)? COUNT(\*) считает абсолютно все строки, а COUNT(price) не учитывает строки со значением NULL в столбце price.
Урок 11. Подсчёт заказов по клиентам (GROUP BY)
\* Раздел: Блок 3 · Агрегации
\* Тема: Группировка данных GROUP BY
\* Теория: Оператор GROUP BY объединяет записи с одинаковыми значениями в указанных столбцах в отдельные группы. Агрегатная функция затем рассчитывается автономно внутри каждой сформированной группы. Записи с отсутствующим значением ключа группировки (NULL) образуют отдельную самостоятельную группу.
Синтаксис:SELECT customer\_id, COUNT(\*) AS orders\_count
FROM orders
GROUP BY customer\_id;
\* Задание: Для каждого customer\_id посчитайте количество оформленных заказов (orders\_count). Отсортируйте результат по убыванию количества заказов.
\* Подсказка: Сгруппируйте данные по идентификатору клиента и отсортируйте по вычисляемому полю.
\* Решение:
SELECT customer\_id, COUNT(\*) AS orders\_count
FROM orders
GROUP BY customer\_id
ORDER BY orders\_count DESC, customer\_id;
\* Объяснение решения: GROUP BY customer\_id выделяет группы заказов для каждого клиента. COUNT(\*) считает количество строк внутри каждой группы. ORDER BY orders\_count DESC выводит наиболее активных покупателей первыми.
\* Ожидаемый результат: 12 групп (включая группу с customer\_id IS NULL). Примеры: клиент 1 — 3 заказа; клиент 2 — 2 заказа; клиент 3 — 2 заказа.
\* Типичные ошибки: Попытка расчета количества заказов без указания GROUP BY, что приводит к подсчету общеитогового количества по всей таблице.
\* Самопроверка: Почему нельзя просто выводить SELECT customer\_id, order\_id, COUNT(\*) без добавления order\_id в GROUP BY? Реляционные СУБД требуют, чтобы все неагрегированные столбцы из списка SELECT обязательно присутствовали в блоке GROUP BY.
Урок 12. Отбор активных клиентов (HAVING)
\* Раздел: Блок 3 · Агрегации
\* Тема: Фильтрация групп HAVING
\* Теория: В то время как предложение WHERE фильтрует отдельные исходные строки до их группировки, инструкция HAVING фильтрует уже сгруппированные агрегированные данные после исполнения GROUP BY. В связи с этим в блоке HAVING разрешено использовать агрегатные функции (COUNT, SUM и др.).
Синтаксис:SELECT customer\_id, COUNT(\*) AS orders\_count
FROM orders
GROUP BY customer\_id
HAVING COUNT(\*) >= 2;

\* Теория: CTE (WITH) создает временный именованный результирующий набор, который доступен в рамках выполнения текущего запроса. CTE позволяет структурировать сложные запросы, разбивая их на логические и понятные шаги. Синтаксис: WITH cte\_name AS (SELECT ...) SELECT ... FROM cte\_name;.

\* Объяснение решения: CTE category\_prices подготавливает агрегаты средней цены по категориям. Внешний SELECT обращается к CTE как к обычной таблице и применяет простой фильтр WHERE average\_price >= 100.

Урок 19. Анализ истории заказов (ROW\_NUMBER)
\* Раздел: Блок 5 · Аналитические запросы
\* Тема: Оконная функция ROW\_NUMBER()
\* Теория: Оконная функция ROW\_NUMBER() присваивает последовательный номер каждой строке внутри определенного окна. Секция PARTITION BY разделяет набор данных на независимые группы (окна), перезапуская нумерацию с 1 для каждой группы. Секция ORDER BY внутри конструкции OVER(...) определяет порядок нумерации строк.
Синтаксис:SELECT order\_id, customer\_id, order\_date,
ROW\_NUMBER() OVER (
PARTITION BY customer\_id
ORDER BY order\_date ASC
) AS rn
FROM orders;
\* Задание: Напишите запрос, нумерующий заказы каждого клиента по дате оформления. Используйте CTE для фильтрации, чтобы вывести только самый первый заказ для каждого покупателя.
\* Подсказка: Примените ROW\_NUMBER() OVER (PARTITION BY customer\_id ORDER BY order\_date ASC) внутри CTE, а во внешнем запросе отберите записи со значением rn = 1.
\* Решение:
WITH ranked\_orders AS (
SELECT order\_id, customer\_id, order\_date, total\_amount,
ROW\_NUMBER() OVER (
PARTITION BY customer\_id
ORDER BY order\_date ASC, order\_id ASC
) AS rn
FROM orders
WHERE customer\_id IS NOT NULL
)
SELECT order\_id, customer\_id, order\_date, total\_amount
FROM ranked\_orders
WHERE rn = 1
ORDER BY customer\_id;
\* Объяснение решения: PARTITION BY customer\_id разбивает заказы по клиентам. ORDER BY order\_date ASC гарантирует, что самый ранний заказ получит номер rn = 1. Внешний запрос фильтрует записи по rn = 1, выставляя первые заказы каждого клиента.
\* Ожидаемый результат: Набор уникальных первых заказов клиентов.
\* Типичные ошибки: Попытка использовать фильтрацию WHERE ROW\_NUMBER() ... = 1 напрямую в том же блоке (оконные функции рассчитываются на этапе формирования вывода и требуют применения CTE или вложенного подзапроса).
\* Самопроверка: В чём отличие ROW\_NUMBER() от RANK()? ROW\_NUMBER() всегда присваивает строкам строго уникальные непрерывные номера, в то время как RANK() присваивает одинаковый ранг при совпадении значений сортировки.
Урок 20. Ранжирование клиентов по объёму покупок (RANK, DENSE\_RANK)
\* Раздел: Блок 5 · Аналитические запросы
\* Тема: Оконные функции ранжирования RANK() и DENSE\_RANK()
\* Теория: Аналитические функции RANK() и DENSE\_RANK() вычисляют ранг строки в упорядоченном наборе. При наличии одинаковых значений RANK() оставляет пропуски в нумерации (например: 1, 2, 2, 4), а DENSE\_RANK() формирует плотный ряд без пропусков (например: 1, 2, 2, 3).

GROUP BY customer\_id;

GROUP BY customer\_id
ORDER BY client\_rank;
\* Объяснение решения: Агрегированная сумма покупок передаётся в аналитическое окно OVER (ORDER BY SUM(total\_amount) DESC), распределяя места клиентов от максимального чека к минимальному.

Урок 21. Анализ динамики продаж по месяцам (LAG)
\* Раздел: Блок 5 · Аналитические запросы
\* Тема: Смещение данных LAG()
\* Теория: Функция LAG(column, offset) позволяет обратиться к значению предшествующей строки без использования самосоединения таблицы (SELF JOIN). Это незаменимо при анализе помесячной динамики выручки (MoM) или прироста показателей.

FROM monthly\_sales;
\* Задание: Рассчитайте сумму продаж за текущий месяц и выведите сумму продаж предыдущего месяца для расчета динамики.
\* Решение:
WITH monthly\_summary AS (
SELECT STRFTIME('%Y-%m', payment\_date) AS month,
SUM(paid\_amount) AS payments\_total
FROM payments
GROUP BY STRFTIME('%Y-%m', payment\_date)
)
SELECT month, payments\_total,
LAG(payments\_total, 1) OVER (ORDER BY month) AS prev\_month\_total,
payments\_total - LAG(payments\_total, 1) OVER (ORDER BY month) AS absolute\_change
FROM monthly\_summary
ORDER BY month;
\* Объяснение решения: CTE рассчитывает итоговые суммы по месяцам, а оконная функция LAG обращается к значению предыдущей строки хронологического ряда.
\* Ожидаемый результат: Таблица с динамикой выручки, где в первой строке значение prev\_month\_total равно NULL.
\* Самопроверка: Что вернёт LAG(), если предыдущей строки не существует (первая запись выборки)? Возвращается значение NULL.

Урок 24. Итоговый аналитический отчёт по клиентам (Комплексный запрос)
\* Раздел: Блок 5 · Аналитические запросы
\* Тема: Комплексный SQL-анализ
\* Теория: Завершающий урок объединяет изученные конструкции SQL: соединения таблиц (LEFT JOIN), агрегации (SUM, COUNT), группировки (GROUP BY), условную логику (CASE WHEN), обработку пропусков (COALESCE) и оконные функции (DENSE\_RANK).
Задание: Составьте итоговый аналитический отчёт по каждому клиенту. Выведите: Имя клиента, Регион, Количество заказов, Общую сумму трат, Категорию клиента ('VIP' при тратах >= 500, иначе 'Regular') и Ранг клиента по тратам. Замените пропуски в заказах на 0.
\* Решение:
WITH customer\_aggregates AS (
SELECT c.customer\_id,
c.customer\_name,
c.region,
COUNT(o.order\_id) AS total\_orders,
COALESCE(SUM(o.total\_amount), 0) AS total\_spent
FROM customers c
LEFT JOIN orders o ON c.customer\_id = o.customer\_id
GROUP BY c.customer\_id, c.customer\_name, c.region
)
SELECT customer\_name,
region,
total\_orders,
total\_spent,
CASE
WHEN total\_spent >= 500 THEN 'VIP'
ELSE 'Regular'
END AS customer\_tier,
DENSE\_RANK() OVER (ORDER BY total\_spent DESC) AS spend\_rank
FROM customer\_aggregates
ORDER BY spend\_rank, customer\_name;
\* Объяснение решения:
1. CTE customer\_aggregates использует LEFT JOIN для объединения всех клиентов с их заказами, исключая потерю клиентов без покупок.
2. COALESCE обрабатывает клиентуру без заказов, заменяя NULL суммы на 0.
3. В основном SELECT выражение CASE WHEN сегментирует аудиторию на VIP/Regular.
4. Оконная функция DENSE\_RANK() производит итоговое ранжирование клиентов по их ценности для бизнеса.
\* Ожидаемый результат: Сводная аналитическая таблица со всеми 12 клиентами, их показателями, статусами и рангами.
