Классификация категорий проблем и стандарты обработки
При проведении проверок качества данных все выявленные аномалии разделяются на пять ключевых категорий. Важнейший профессиональный принцип — не изменять и не перезаписывать исходный CSV-файл молча.
1. Точные дубликаты (exact duplicate / duplicate)
\* Определение: Полностью повторившиеся строки с идентичными значениями во всех полях с учётом заданного уровня детализации.
\* Правило обработки: Удалять исключительно полный дубликат, сохраняя ровно одну оригинальную строку. Уникальность определяется по всем значимым столбцам, а не по единичному идентификатору.
2. Пропущенные обязательные поля (missing values / missing)
\* Определение: Отсутствие критически важных бизнес-значений, таких как дата заказа (order\_date) или идентификатор клиента (customer\_id).
\* Правило обработки: Категорически запрещено придумывать даты или автоматически заменять пропущенные тексты нулями. Записи с пропусками переносятся в отдельный список исключений (карантин) для согласования с владельцем данных.
3. Несогласованный формат (formatting issues / format)
\* Определение: Нарушение стандартов записи данных, включая нестандартные форматы дат (например, YYYY/MM/DD вместо YYYY-MM-DD), непечатные пробелы и разный регистр текстовых категорий (delivered вместо Delivered).
\* Правило обработки: Выполняется автоматическая приведение к единому стандарту: даты форматируются в YYYY-MM-DD, удаляются лишние пробелы, текстовые статусы канонизируются к единому регистру.
4. Некорректные числовые значения (numeric errors / numeric)
\* Определение: Наличие строкового текста в числовых столбцах (например, unknown), нулевые количество/цена при активных доставленных статусах, либо отрицательная цена.
\* Правило обработки: Данные записи изолируются в список проверки. Необходим предварительный бизнес-анализ: отрицательное количество при статусе «Returned» может являться легитимной операцией возврата товара. Отрицательная цена или нулевое количество при доставке выносятся в карантин.
5. Подозрительная дата (out-of-bounds date / date)
\* Определение: Даты, выходящие за границы допустимого временного диапазона относительно даты выгрузки (например, даты из будущего).
\* Правило обработки: Строки с датами, превышающими контрольную дату выгрузки (20 января 2026 года), изолируются для проверки расписания загрузки и источника.
Стандартный алгоритм очистки данных (SOP)
1. Сохранить исходный файл данных и сформировать его резервную копию без редактирования.
2. Проверить уровень детализации и подтвердить правила идентификации записей.
3. Выполнить автоматическое исправление безопасных форматно-регистровых несоответствий.
4. Изолировать неполные, некорректные и подозрительные строки в реестр исключений.
5. Сверить контрольный баланс: Количество исходных строк = Очищенные строки + Исключённые строки.
